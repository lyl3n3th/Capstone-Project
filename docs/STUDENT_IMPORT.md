# Import existing students

Apply `supabase/migrations/20261019000500_existing_student_import.sql` in Supabase SQL Editor after the branch offering and protection migrations (`20261019000100` through `20261019000400`). Then apply `20261019000600_student_import_school_history.sql` to add Last School Attended and Year Completion. This adds the import RPCs, the Existing Student admission classification, and durable academic year, semester, and standing metadata. No existing student records are changed by applying the migration.

On the branch administrator's Students page, select **Import Students** and download the template. The workbook includes Students, Instructions, and Branch Offerings sheets, plus a hidden Dropdown Options sheet. Fill in the original student number, personal and contact information, educational level, grade/year level, course/strand, academic year, branch, semester, Regular/Irregular standing, last school attended, and completion year. Birthdays use MM/DD/YYYY (for example, 08/21/2005). The five academic selection fields have Excel dropdowns through row 501. Educational Level lists only levels offered by this branch; grade/year, course/strand, and semester dropdowns depend on that level. Redownload the template after this update. Middle name and guardian details are optional. Section is intentionally excluded: imported records have a null section so staff can assign one after import.

Upload an `.xlsx` or `.xls` file, up to 10 MB and 500 student rows. The editable preview identifies each incorrect Excel cell (for example, I2), highlights it, and lets staff jump to the cell. Staff can filter error rows, remove rows, or download an error report. Column reordering is supported; renamed, missing, duplicate, unexpected, or formula headers must be corrected in the workbook. Formula values are rejected. The template formats IDs and phone numbers as text to preserve leading zeros.

The server revalidates the entire batch against active branch offerings and existing IDs/emails. It saves all rows together or none. Existing students are never overwritten. Imported students are active, classified as Existing Student, and retain their original student numbers. Credentials remain incomplete until documents are supplied. Imported year/semester and standing survive refresh; the term appears in Student Details. The import does not create admission applications or assign portal passwords.

Verification: `npm run test:student-import` covers workbook parsing, leading zeros, original cell references, duplicates, formulas, required headers, dates, branch offerings, and standing validation. `npm run build` checks TypeScript and the production bundle. The migration was also exercised in isolated PostgreSQL for full rollback, durable metadata, branch restrictions, duplicates, SHS/College records, and offering deletion protection. Browser verification used mocked network responses, with no real student writes.

## Historical grades for imported students

Apply `supabase/migrations/20261019000700_imported_student_historical_grades.sql` after the import migrations. In Student Details, imported students have a Previous Years and Semesters section. A 4th Year student imported for 2026-2027, 1st Semester gets both semesters of 1st Year (2023-2024), 2nd Year (2024-2025), and 3rd Year (2025-2026). An imported second semester also includes the first semester of that year. Grade 12 students similarly see Grade 11 and any earlier semester of Grade 12. Regular historical terms include the two main semesters; summer attendance is not inferred.

Subjects come from the branch curriculum for the student's course/strand, year level and semester, including common subjects. Empty terms show configuration guidance. Review this current curriculum against the student's original records; the system cannot reconstruct a former curriculum that was never configured. Empty cells display Not recorded and are never stored as grades or included in calculations.

Select Enter grades for a subject, choose its original instructor from the branch instructor list, and enter the College percentage final grade (50–100 or INC/FAILED/DRP) or the SHS quarter grades (60–100). Missing quarters remain blank. Save waits for the database before reporting success. The database validates the student's imported placement, course/subject, term, grade range and instructor branch, and saves the subject's quarters atomically. Attribution is stored with the grade; no teaching assignments or instructor submissions are fabricated. Original student numbers are preserved, including legacy numbers containing letters.

Saved historical grades can be edited in the historical section. Normal uploaded grades are shown without allowing the historical editor to overwrite them. Historical grades appear in the existing grade lists and academic standing calculations. Remove saved grades through the existing Uploaded Grades controls. If the original instructor is absent, add their profile in Instructor Management before selecting them. Grades retain the recorded instructor name even if that instructor is later removed.

Run `npm run test:historical-grades` for chronology, curriculum filtering, legacy identity, placeholder exclusion, standing, and grade removal checks. The SQL and browser paths were also tested in isolated/mock environments for persistence, instructor attribution, invalid grades and atomic saves; no live student grades were written during verification.

Imported students can see their current curriculum subjects for the imported year level, academic year and semester even while their section is unassigned. Missing schedule, time, room and instructor details display TBA. When a section has assignments, those details take precedence and matching unscheduled curriculum subjects remain visible. Imported curriculum lookup stays within the branch and course/strand. Explicit approved own-schedule/enrollment loads retain precedence. Run `npm run test:imported-subjects` to verify these rules.


## Imported irregular students and instructor workflows

Imported Irregular standing enables the existing own-schedule planner for the imported academic year and semester. This is permission to choose schedules, not approval of any chosen assignment. Students select available schedules and submit for admin/registrar approval. Schedule options remain within the course and current term; eligibility uses uploaded grades and prerequisites. An unscheduled curriculum subject can remain visible while its offering is being configured.

Once approved through Schedule Approvals, the approved subject plan determines the student's instructor assignments, including students with no block section. Instructor Students, grade templates/uploads, and change-of-grade lists/templates use those approved assignments. Pending students and unselected subjects do not enter an imported irregular student's instructor roster through block-section membership. Instructor loading fetches the remote roster and individual plans, so another browser does not depend on an administrator's local cache.

Grade uploads and changes retain imported original student numbers and instructor attribution. Schedule requests also use original IDs so legacy IDs with the same digits stay separate. A failed schedule save reports an error rather than pretending a local-only request was submitted. No new database migration is needed beyond the existing import and planning migrations.

Run `npm run test:imported-scheduling` for approval gating, refreshed instructor rosters, generated templates, real Excel upload/change parsing, original IDs, selected-subject scope, and failed-save handling. Browser checks exercise the planner, pending submission and approved schedule display using mocked network responses.
