The area manager dashboard and student directory load their student population from Supabase through `fetchAdminStudents`, the same reader used by the admin student list. Each page fetches the managed branch list and then requests students for those branches. Opening an admin page is no longer required to populate a browser cache first.

Both manager pages share the same active student snapshot. Archived and graduated students are excluded, along with deleted, inactive, and removed records. A branch with no students shows zero; cached applicants are never substituted for enrolled students. The dashboard's SHS/College breakdown also uses this student snapshot.

Records refresh on page load, window focus, and student cache change notifications. Cache notifications trigger a database refresh rather than replacing the displayed data with local records. No student cache is written by the manager reader. Failed loads show an error and a retry button. Failed refreshes preserve the last successfully fetched snapshot and label it accordingly; one failed branch cannot produce a partial total presented as complete. Report-loading failures do not erase student counts.

No database migration is required. Run `npm run test:manager-students` and `npm run build` to validate the reader and production bundle. Browser verification covered 8 cached versus 25 database records, independent dashboard/directory loads, empty branches, lifecycle filtering, focus refresh, student removals and pagination, failed loads and retries, and report failures using mocked network responses.
